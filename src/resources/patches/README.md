# Game patches the core carries

The patch files of two repositories, and the core's own, built into the core (`src/common/embedded_resources.h`) and listed per game in the Patch Manager core options (`src/common/patch_catalog.h`). They are the two repositories standalone shadPS4 downloads its patches from.

- `shadPS4/`: the `PATCHES` folder of [shadps4-emu/ps4_cheats](https://github.com/shadps4-emu/ps4_cheats), commit `cf33d5bae8bd82f483c0aed3f09b2d9e94fe6419`.
- `ParaLLEl/`: the core's own patches, in the same format, with one kind of line of its own: `mask_halve` finds a pattern as `mask` does and halves the decimal number of `Size` bytes at `Offset` from it, where it is (`src/common/patch_halve.h`). Two patches for Bloodborne, Dark Souls III and Sekiro, whose sound engine is FromSoftware's MagicOrchestra over FMOD Ex 4.44. `Double Sound Update Rate`: the engine carries its setup as `Key= value` text in the executable and takes the game's sound orders once every `MainThreadUpdateTime` microseconds, 33333; the patch halves whatever the value is by then (16666, or 8333 after Bloodborne's 60 FPS++, which writes 16666 itself). `Lower Audio Latency`: FMOD mixes ahead in 4 blocks of 256 samples (its own default: the setup text has no `DspBufferSize` or `DspBufferNum`, which the game would pass to `System::setDSPBufferSize`), 21 ms at 48 kHz; the patch finds where FMOD's code sets them and makes it 2 blocks, 11 ms, the fewest FMOD takes, a block being already the console's shortest. Neither names an `AppVer`: they apply to every version of the game that has the text and the code. Bloodborne has three more, `Highest`, `Lower` and `Lowest Model Detail Everywhere`: the game picks a model's detail level, 0 to 2, in five places, each adding an offset read from one global to the level from the model's LodBank distances and keeping the sum within 0 to 2; the patches put -2, 1 or 2 in place of the global in all five, each found by a byte pattern that occurs once in the 1.09 eboot. They replace shadPS4's `Model LOD -2`, `1` and `2` (Kyo, auser1337), which changed only one of the five.
- `GoldHEN/`: the `patches/xml` folder of [illusion0001/PS4-PS5-Game-Patch](https://github.com/illusion0001/PS4-PS5-Game-Patch) (the PS4 patches; `patches/xml_prospero` is the PS5's), commit `65914503123d4e643aa5aa0e8c720de8e99ef7e8`.

The files are as the repositories have them, with three changes: line ends are LF; `BloodborneNetworkTest`, which has no extension there, is `BloodborneNetworkTest.xml`; shadPS4's `Bloodborne.xml` has no `Model LOD 2`, `Model LOD 1` and `Model LOD -2`, which the core's Model Detail patches replace, and no `30 FPS++` to `960 FPS++` and `Uncap FPS++`, which the core's Frame Rate group replaces; and GoldHEN's `Bloodborne-Orbis.xml` has `Group="Frame Rate"` and a `Choice` on `30 FPS Fix (Proper Frame Pacing)`, `60 FPS (With Deltatime)` and `Disable vsync`, which write the same code, and `Group="Resolution"` on its `Resolution Patch (720p)`; shadPS4's `Bloodborne.xml` has a `Group` and `Choice` (and on the first of each, a `GroupNote`) on its resolution patches (the Resolution Patches, `Optimal 1080p` and the Decoupled 1080p UI ones, which write the same code: one Resolution option), its HD Motion Blur ones (Motion Blur Resolution) and its Light Grid ones (Light Grid). An update keeps those. Their `isEnabled` attributes are not read: the core options say which patches are on.

To update, copy the folders over again the same way and note the new commits here. The build embeds every `.xml` in the three folders, shadPS4's first, then GoldHEN's, then the core's: for a patch of the same name and game version in both, shadPS4's is the one applied.

## Groups and rates

The core's own attributes, which the other repositories' files may carry too:

- `Group`: patches of the same group are one Patch Manager option, a choice among them (they write the same code). `Choice` is a patch's label there; without it, its name. The core's own patches come first.
- `Rates`: the patch is one choice for each rate in the list (`60,90,144,display`), its `Choice` with `%u` for the rate; `display` is the display's refresh rate, worked out when the game starts ("Match display"). Its lines can be the core's own `rate_f32`, `rate_u32` and `rate_dec` (`Size` digits), whose `Value` is a formula of `N`, the rate (`1/N`, `990000/N`, `0.65^(30/N)`; `src/common/patch_rate.h`), and any line can be limited to some rates with `MinRate` and `MaxRate`.
- `GroupNote`: the group option's description, from the first patch of the group that has one; without it, each patch's note.
- `FrameRate="1"`: the rate picked is the game's frame rate: the core runs the frontend, the game's time and the console's vblanks at it.

Bloodborne's Frame Rate group: `Frame Rate` is shadPS4's 60 to 960 FPS++ made one patch, the 15 values that change with the rate (the frame time, 1/N, in ten places; 3/N, 1/(2N), N/6, N/3, 990000/N; the sound engine's update time, 1000000/N as text; a table of 0.8, 1.2 and 0.65 to the power 30/N, and N) written as formulas, and the six jumps and the code that rates above 60 add limited to them. At 60, 90, 120, 180, 240, 360, 480 and 960 it writes exactly the bytes their FPS++ wrote; it adds 144, 165 and the display's. `Frame Rate 30, Lower Input Delay` is shadPS4's 30 FPS++ and `Uncapped Frame Rate` its Uncap FPS++, as they were.
