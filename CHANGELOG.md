# Changelog of the libretro core

What changed in the libretro core of this fork, newest first. Changes that come with a merge of upstream shadPS4 are in upstream's own history; a merge is noted here with the upstream commit it brought in.

## Unreleased

- libretro-common synced with RetroArch: TLS handshakes can now be stepped without blocking, UPnP can reuse a gateway it found before and try other external ports, and an Adler-32 helper and a GIF image type were added. The core calls nothing new yet.
- FreeType is gone, along with the `externals/freetype` submodule. libSceFont and libSceFontFt read fonts with libretro-common's rtt, TrueType and CFF (CID-keyed included), in place from the bytes they were given: the system fonts the core carries, a game's font in memory, and a host font file read once through libretro-common's file streams. Nothing is copied and no library state is kept. Sizes, metrics, advances, kerning, outlines and bitmap boxes are worked out as FreeType works them out for an unhinted glyph, with the same 26.6 and 16.16 rounding, and match it number for number on the fonts tested. The coverage values inside a bitmap differ from FreeType's by under one level in 255 on average. A glyph's bitmap and outline buffers are kept and reused from one glyph to the next. Bitmap-only fonts are no longer read, and a missing character is no longer looked for in a font's other character maps; rtt picks the best Unicode one. Needs RetroArch's rtt points and components patch.
- The `half` library is gone, along with the `externals/half` submodule. The one half-float conversion the core made, turning 16-bit float clear colours into Vulkan clear values, uses libretro-common's `math/float16.h`, which gives the same exact values.
- Boost.Asio is no longer used. The kernel's event-queue timers ran on an Asio io_context, on a service thread woken through a mutex and condition variable. They now run on a timer thread of their own: arming a timer posts it to a lock-free ring, the thread keeps the armed timers in a heap reserved up front and sleeps on an eventcount until the first is due. Removing or re-arming a timer leaves the old entry to be dropped when it comes up, by a generation number, instead of cancelling it. Periodic timers still fire a period after the last firing, not after the callback ran.
- wepoll is gone, along with the `externals/ext-wepoll` submodule. On Windows a guest epoll is now a table of registrations polled with select() through libretro-common's `socket_poll`, which also takes more than 64 sockets now. Waiting threads read the table without a lock: each entry is a seqlock, written one at a time under the guest epoll's lock, and a one-shot entry is taken by one waiter only, by compare-and-swap. A change while a thread waits wakes it through the epoll's existing wake socket, so it polls the new set at once. The socket-pair and single-socket waits use `socket_poll` too, so a refused connect is reported straight away, where WSAPoll on older Windows never reported it.
- epoll-shim is gone, along with the `externals/epoll-shim` submodule. macOS and FreeBSD built and linked it, but the network layer already uses kqueue directly there, so nothing called it.
- The `date` library is gone, along with the `externals/date` submodule. It was built and linked on macOS and FreeBSD for a time-zone header that nothing used any more: the time zone comes from the C library's `localtime_r` there as on Linux.
- MP3 music plays gapless. libretro-common's rmp3 now reads the Xing/Info tag frame and LAME's encoder delay and padding: the tag frame is no longer decoded as a frame of silence, and the encoder's delay, the decoder's own 529 samples and the encoder's padding come off, so a track is exactly as long as what was encoded and loops without a gap. The track's length comes from the tag, so its buffer is allocated once at the right size.
- libSceAvPlayer's queues are lock-free. Packets, guest buffers and decoded frames move between the demuxer, the decoders and the game through libretro-common's waitable SPSC rings, one thread at each end, and a waiting thread sleeps on an eventcount instead of a mutex and condition variable. The guest buffers are made once at Start and the rings carry their indices, so nothing is allocated while playing. A decoder keeps a buffer it could not fill instead of handing it back. Stop closes the rings, which wakes every waiting thread at once. The event queue the controller thread reads is a lock-free ring as well. The demuxer's queues are now bounded: it waits when a decoder is 4096 samples behind.
- spdlog is gone, along with the `externals/spdlog` submodule. The log has one writer thread: other threads format a line on their own stack and post it through a lock-free ring, so logging takes no lock and allocates nothing (the thread name is now written into a buffer too). Files are written with libretro-common's file streams; the console keeps its colours. The settings keep their meaning: the per-class filter, the flush level, the session file with its size limit, append or truncate, and skipping duplicates. With sync logging (the default) every line is kept, a thread waiting only while the ring is full; with async logging a line that finds the ring full is dropped, and the count is logged. A critical line is always kept. Files are flushed whenever the writer runs dry, and `Flush()` waits until it has.
- cpp-httplib and LibreSSL are gone, with their submodules. libSceHttp and NP invitations send their requests with libretro-common's net_http, and HTTPS goes through libretro-common's own TLS 1.2/1.3 client. The PS4 redirect rules, the game's own headers and certificate-verification choices are kept. P2P packet encryption and signing use libretro-common's crypto: AES-128-CFB, HMAC-SHA1 and the platform's random bytes, with the same bytes on the wire. net_http's connection pool and DNS cache belong to one thread, so all of it now runs on a single network-service thread: callers hand it work through a lock-free ring, and a libSceHttp call waits on an eventcount for its own request, as the game asked it to. UPnP runs there too instead of on a thread of its own.
- LibAtrac9 is gone, along with the `externals/LibAtrac9` submodule. libSceAjm's ATRAC9 decoder now uses libretro-common's ratrac9, a clean-room decoder that gives bit-identical output and decodes about 2.8x as fast. A reset keeps the decoder's memory instead of freeing and allocating it again. Draining the rest of a superframe at the end of a track reuses the frame buffer instead of allocating one. A frame cut short no longer steps past the end of the input. The WAVE header's config is read with `ratrac9_parse_wave_fmt`.
- FFmpeg is gone, along with the `externals/ffmpeg-core` submodule. libSceAvPlayer, the last part that used it, now demuxes with libretro-common's rmp4, decodes video with rh264/rh265 and decodes AAC with raac. A host file is memory-mapped and its samples handed to the decoders in place. A file read through the game's callbacks or a backend handle is read into place as the demuxer reaches it: the header first, where it lies, even at the end of the file, then each sample in file order, every byte read once. Pictures are decoded straight into the game's frame buffers, and AAC into its audio buffers, with the encoder delay the edit list trims taken off the start. This also fixes the build: avplayer still called a video helper the videodec change had removed.
- libSceVdecsw is lock-free: the game's calls post to the decoding thread through a ring and take results and pictures from two more, with no mutex or condition variable left. The Sync calls wait on an eventcount, as the game asked to wait; the Try calls never wait. Access units are copied into buffers kept with the ring's slots, and pictures are decoded straight into the picture ring's buffers, so after warm-up nothing is allocated per access unit or picture. A reset starts a new epoch, and results from before it are dropped as they are read. `SetDecodeInput` returns `OUTPUT_PENDING` when the pictures not yet taken, plus the inputs in flight, would overrun the picture ring.
- The game's video decoders (libSceVideodec, libSceVideodec2 and libSceVdecsw) decode H.264 with libretro-common's rh264 and HEVC with rh265 in place of FFmpeg. Each picture is written as the console's NV12 frame in one pass from the decoder's planes, where FFmpeg's scaler first made an NV12 copy that was then copied again. A reset hands out and drops the pictures held for display order, and frees nothing. libSceVdecsw's queue of pictures decoded ahead reuses its buffers rather than allocating one per picture.
- The music player decodes AAC with libretro-common in place of FFmpeg: `.aac` (ADTS) with raac, `.m4a`/`.mp4` with rmp4 and raac, the track's edit list trimming the encoder delay. The decoded track is now one malloc'd buffer that rmp4's output is taken over into without a copy, and that MP3 and FLAC grow in place. The file extension is matched in any case.
- The game's MP3 decoder (libSceAjm's MP3) decodes with libretro-common's rmp3 in place of FFmpeg, frame by frame straight from the game's input, without a parser holding back data between jobs. Float and 32-bit output come from rmp3's float synthesis, 16-bit from its fixed-point one; FFmpeg's resampler is no longer involved. A frame whose bit reservoir reaches back before the stream was joined comes out as silence of the frame's length. Needs RetroArch's two rmp3 patches (float frame decode, a frame with part of the next behind it).
- miniupnpc is gone: the P2P port is forwarded through the router with libretro-common's `net/net_upnp.h`. Finding the router, mapping and unmapping now all happen on one thread of its own; callers only post the port they want forwarded and never wait for the router. The mapping is removed when the core shuts down. Needs RetroArch's net_upnp patch.
- The hwinfo library is gone: the CPU model and core counts in the log come from libretro-common's `features/features_cpu.h`. The total RAM and the operating system are no longer logged by the core; RetroArch's log has both.
- The Tracy profiler is gone: its hooks in the HLE libraries, the renderer and the GPU command processor, its Vulkan timestamp context and the library. Debug builds no longer open a profiler connection.
- fdk-aac is gone: the game's AAC decoder (libSceAjm's M4AAC) decodes with libretro-common's raac, AAC-LC, HE-AAC and HE-AAC v2 alike, from ADTS or raw streams. Each frame is decoded straight into the game's output buffer, in float when the game asks for float. 7.1 streams now come out as the eight channels the game asked for, where fdk-aac folded them down to 5.1, and without fdk-aac's output limiter, which reshaped and delayed the sound. HE-AAC frames now hand over all of their 2048 samples per channel; only the first 1024 were written before. Needs RetroArch's raac patches (ADTS header parse and WAVE channel order, parametric stereo).
- nlohmann::json is gone: nothing in the core uses it any more. The core no longer carries the library.
- The emulator settings (`config.json` and the per-game files in `custom_configs/`) and the users (`users.json`) are read and written in C89 with libretro-common's rjson, in place of nlohmann::json; the C++ classes and their per-call lock are gone. Members of those files this build doesn't know are kept when they are written, as before. Each file is written to a temporary file first and then renamed over the old one. A setting of the wrong type is now logged and left at its value, where a bad file stopped the core; a broken file is replaced with a good one. Strings are held in fixed buffers (256 octets, 4096 for paths), at most 16 game install directories and 16 users are kept. A `config.json` written now lists its keys in the order the core knows them rather than sorted.
- The HTTP host overrides (`host_overrides.json`), the patch repositories' `files.json` index and the body of a shadNet session invitation are read and written in C89 with libretro-common's rjson, in place of nlohmann::json. At most 64 host overrides are kept; more are logged and skipped.
- The key file (`keys.json`) is read and written in C89 with libretro-common's streaming JSON parser and writer (`formats/rjson.h`), in place of nlohmann::json. It is written to a temporary file first and then renamed over the old one, so a failed write no longer leaves it half-written. It is no longer written again when the core shuts down.
- stb_image and stb_image_write are gone: the overlay's PNGs (trophy icons and the like) decode with libretro-common's rpng. A PNG that fails to decode is now skipped instead of uploaded from a null image.
- CLI11 and ImGuiFileDialog are no longer built: nothing in the core used them.
- pugixml is replaced by libretro-common's rxml for the trophy files and the memory patches. A file is parsed in place from the buffer it is read into. Comments in a user's trophy progress file are not kept when it is written back.
- libpng and zlib-ng are gone: the game's PNG libraries (libScePngDec, libScePngEnc) decode and encode with libretro-common's rpng. A PNG decodes straight into the game's image buffer and encodes straight into its output buffer. An RGBA encode now honours the game's row pitch, which it ignored before. With this, the core carries no zlib at all.
- ZArchive and zstd are replaced by libretro-common: a game packed as a `.zar` is read with `formats/zar.h` from a memory mapping of the archive (`streams/file_stream.h`). Reads no longer pass through one shared worker thread under a lock: each thread reads on its own, and a file's octets go straight to where the game wants them. Paths inside an archive are now matched without regard to ASCII case. The AMD reciprocal tables decode with `encodings/rzstd.h`.
- The core's own inflating no longer uses zlib: PKG blocks and gzip HTTP bodies inflate with libretro-common's `encodings/deflate.h`. A gzip body is inflated into a buffer of the size its trailer records, made once. zlib-ng is left only for libpng, which the game's PNG libraries are built on.
- miniz is gone. The game-facing zlib library (`sceZlibInflate`) inflates with libretro-common's `encodings/deflate.h`. The pipeline cache is always kept as files in the game's cache folder: the zip-archived form (`pipeline_cache_archived`, off by default and not a core option) is gone with its setting.
- minimp3 and dr_flac are replaced by libretro-common's MP3 and FLAC decoders (`formats/rmp3.h`, `formats/rflac.h`) for the music player and the custom trophy sound. A track is decoded straight into the buffer it plays from, with no copy afterwards, and a track decoded with FFmpeg (AAC, M4A, MP4) is no longer copied once more after decoding.
- xxHash is replaced by libretro-common's XXH3 (`encodings/xxh3.h`), which gives the same hashes. Hashing a texture's backing memory no longer allocates.
- Discord Rich Presence is gone (it was off by default, and the core builds were made without it), with its `discord_rpc_enabled` setting and the discord-rpc library.
- SDL3 is gone from the core: no longer built, linked or carried. Building on Linux no longer needs the ALSA, PulseAudio, GLES, EGL or GL development packages.
- The emulator no longer makes a hidden SDL window, nor runs an SDL event loop: the core's input comes only from RetroArch's ports, and a mouse or keyboard a game asks for reads as not connected. Gone with it: the keyboard, mouse and gamepad bindings of standalone shadPS4 (its input configuration files and hotkeys), SDL's gamepads and their light bar, gyro and rumble (rumble goes through RetroArch, as before), the quit dialog, and the settings only those read (`cursor_state`, `cursor_hide_timeout`, `motion_controls_enabled`, `use_unified_input_config`, `default_controller_id`, `background_controller_input`, `use_mice_as_mice`, `use_keyboard_as_keyboard`). The one-time prompt to migrate saves and trophies from standalone shadPS4's old layout goes too. The overlay is now drawn at the size of the picture when Resolution is Default, not at the configured one.
- The microphone and the camera no longer open the system's own devices through SDL, past RetroArch. A game finds no microphone (it reads silence, at a microphone's pace) and no camera attached, which was already the camera's default. Both now take their input from a backend of their own, so RetroArch's microphone and camera can be plugged in later. The `sdl_mic_device` and `camera_id` settings are gone.
- The old configuration is no longer carried over: a `config.toml` from before the JSON settings is not offered for migration (that asked with an SDL message box, which a core cannot show) and its trophy key is not read, network keys under `General` and the `WindowsGuestRedZoneProtection` section are no longer read as their current names, and the audio keys for the removed backends (`audio_backend`, `openal_*`, `sdl_main_output_device`, `sdl_padSpk_output_device`) are gone; a `config.json` that has them loads and drops them when saved. The toml11 library goes with it.
- The trophy sound and the music player (a game's custom soundtrack) are played through RetroArch, in the core's mix, where each opened an audio device of the system's own past RetroArch, its volume, latency and recording. The trophy sound, built-in or the custom `trophy.mp3`/`trophy.wav` in the user folder, is decoded and resampled once when the game starts, so a trophy unlocked in play decodes nothing; the custom WAV file is read in place. Sound that is not the console's own 48 kHz is resampled with a 16-tap windowed sinc. The Volume option now applies to the music player as well.
- Sound no longer goes through SDL. Each audio port converts what the game writes to 16-bit stereo, with its volume, straight into an input of the core's own mix, which hands it to RetroArch; 16-bit stereo ports pass through unchanged, where SDL converted them to float and back. A port that waits for RetroArch to take sound is woken the moment it does, where it looked again every millisecond, and nothing is allocated while the game plays. The mix uses libretro-common's lock-free rings and eventcounts, now in the source under `libretro/libretro-common/`.
- The CMake option ENABLE_TESTS is gone: it could only stop the configure step, as upstream's tests are not in this repository.
- The standalone's big-picture launcher and in-game settings dialog, its window icons and its screenshots are gone from the source. None of them could be reached in the core, whose window is hidden and gets no keys: RetroArch takes screenshots, and the emulator's settings are core options. The core no longer makes an empty `screenshots` folder in `system/shadPS4/`, and no longer reads the game's icon at start to put on a window nobody sees.
- OpenAL is gone, and with it the emulator's audio backend setting: Audio3D always goes out through the frontend. With `audio_backend` set to OpenAL in the emulator's config file, a game's Audio3D sound went straight to the system's audio device, past RetroArch and its volume, latency and recording; it now comes through RetroArch like the rest of the sound. The core is smaller by the OpenAL Soft library it carried.
- The standalone's window presentation is gone from the source: the Vulkan surface, the real swapchain with its present modes and semaphores, and the HDR swapchain switch, none of which the core ever used. The game is told there is no HDR output, as it was before.
- The source builds the core and nothing else: the CMake option ENABLE_LIBRETRO and the LIBRETRO define are gone, along with the standalone's code paths they kept apart (its window, fullscreen and icon handling, its audio device and OpenAL backend selection, the swapchain on a window surface, its screenshots of the presented picture, its executable link settings). Nothing changes for someone using the core; a build no longer passes `-DENABLE_LIBRETRO=ON`.
- Linux and macOS: a crash on a thread that is not the game's (RetroArch's own, a driver's) is no longer the emulator's: it goes to the signal handler there was before the core's, so the system's crash report names it, where the core logged it as an unhandled signal and shut the emulator down. When the core takes its handlers out, the ones there were before come back instead of the defaults, so later crashes are reported again (sco8487).
- With PKG Content at Run from PKG, a game that asks for the size of a file it has open (fstat) gets it: since the last merge of upstream, the emulator answers fstat only for a file with an inode, and a file read out of a PKG had none, so the game got an error. Horizon Chase Turbo, a Unity game, stopped at start with an access violation right after opening its `global-metadata.dat`; it now reaches its menu as it does from an installed game.
- Merged upstream shadPS4 up to 8a48cd01 (52 commits): among others additional content from linked services (SERVICE_ID_ADDCONT_ADD) with entitlement keys, posix_flock, scePadReadExt, libSceMusicPlayerService, a fast shader math setting and shader recompiler and texture cache fixes. The core's own handling of additional content (PKGs beside the game's, PKGs that cannot be read) is carried over to upstream's new loader.
- GPUs without sparse buffers at all (Intel HD Graphics 615 and other Intel Gen9 GPUs under Mesa) no longer lose the device on the game's first frame ("Device lost during submit"): the buffer cache's arenas there are plain buffers of 64 MiB, each backed whole by memory of its own from the moment the game first uses that part of its memory, where they were sparse buffers the device cannot make. That costs more memory than on other GPUs. Other devices are untouched. Tried on Linux x86_64 on an Intel HD Graphics 615 (Mesa 25.2.8): Sonic Mania Plus plays, where it lost the device on its first frame before, and Horizon Chase Turbo gets to a race; its picture stays black for the first minutes while its shaders are built the first time, with the music already playing.
- RetroArch no longer crashes when the picture grows past the size it was told at load, as after changing Resolution to a larger one and resetting (the black picture shown until the game draws counts too): the core now has RetroArch size its buffers again (SET_SYSTEM_AV_INFO). With a software video filter on (scanline2x), the filter wrote past its buffer and took RetroArch down.
- Output Resolution is now Resolution, and Default, the new default, renders the game at its own resolution and hands the picture over at exactly that size, taken from the game's video out buffers (it was 1280x720). A Resolution below the game's own is also the size the game renders at: the game's frame-sized render targets and their depth buffers are made that much smaller on the GPU. Before, only the finished picture was scaled down, which saved little. On an Adreno 618 Horizon Chase Turbo runs at 58 frames a second at 960x540 where it ran at 22. Neither the emulator nor upstream could render below the game's own resolution. Effects that read those targets at their full size can come out wrong; Default puts it back. The option has a new key, so a Resolution set before is back to Default once.
- Linux on ARM (aarch64): the core is the emulator built for ARM, running the game's x86-64 code with FEX's CPU core (FEXCore) built into it, in place of carrying box64 and the x86-64 emulator and translating all of them. The core is one 70 MB file where it was 157 MB, and writes nothing into `system/shadPS4/x86_64/` any more (that folder can be deleted). The port is Bachata S4's (zenithblue-oss/shadps4-arm64, MIT), with fixes for running as a core: no static TLS (the frontend loads the core with dlopen), the console's memory mapped at its own addresses, the game's thread stacks and signals as the game's garbage collector needs them (Horizon Chase Turbo stopped in it), shader resource tables read by an interpreter where the x86-64 build runs their code. Games that use fibers (libSceFiber) can start: a switch between fibers sets the game's registers aside and puts the other fiber's in their place. Exact CPU Flags is gone from the ARM core, as it was box64's. Tried on a Snapdragon 7c (Adreno 618, Turnip): Sonic Mania at 60 frames a second, Horizon Chase Turbo in a race at 22 to 23, the same as through box64, as the GPU holds it back; Reset works. Not yet run on a game that uses fibers. The box64 core can still be built, as `box64core` in the CI workflow.
- Resolution can also be 480x270, 320x180 or 800x450 (between 640x360 and 960x540), for slow machines; all keep the 16:9 picture.
- Merged upstream shadPS4 up to 5dad1692 (0.20.0 and after it): among others a garbage collector for the texture and buffer caches, CMask metadata, libSceUsbStorage and the I/O event queue. The core's own changes are kept as they were.
- A game's fake-signed PKG can be loaded as content. With the new core option PKG Content at Run from PKG, the default, it runs straight out of it, with nothing installed: the emulator's file system reads its files out of the PKG, decrypting and unpacking each 64 KiB block as the game reads it, as it reads a `.zar`. At Install the game, its update and additional content are extracted into `system/shadPS4/` the first time and run from there. The update and additional content PKGs beside the game's, of the same title, are taken with it: the update with the highest version laid over the game, the additional content offered to it. The PKG code is upstream's from before it removed it (be22674f), with LibreSSL in the place of Crypto++. The core carries no keys: they go into `system/shadPS4/pkg_keys.txt` (README, Content). Not yet run on a PKG.
- GPUs without 8-bit or 16-bit storage buffer access (Adreno 618 with Turnip among them) show 8- and 16-bit textures right: their detiling went through 8- and 16-bit buffer reads and writes the GPU does not do, and text and some textures came out as stripes (Horizon Chase Turbo's lettering and skyline). There the textures are detiled over 32-bit words; tried on that GPU, where Horizon Chase Turbo's menus and track pictures now read right.
- ARM: box64 tells the emulator a write fault from the CPU's own exception syndrome, where it guessed from the x86 instruction, which says "read" for a fault inside a native function such as memcpy. The emulator then left the page protected and the same write faulted forever: Horizon Chase Turbo stopped while loading, with its threads waiting on a mutex the faulting one held; with the change it gets past the loading and plays.
- Volume, FSR Upscaling, FSR Sharpening, FSR Sharpening Strength, Show FPS Counter and the trophy notification options take effect at once, while the game runs, where they waited for the next start. The other options still apply when a game starts, as the emulator reads them only then.
- Linux: the core links its C++ runtime in, so it no longer needs the frontend's machine to have a matching libstdc++.
- The emulator no longer ends with "Out of order flip IRQ" when a frame's flip comes in later than the emulator expects; it writes a warning to the log and shows the frame. Seen on the ARM machine in Sonic Mania, a while into Mania Mode; upstream has the same assertion fail in other games.
- Reset works: the emulator is ended and the game started again in a new emulator process. Before, the frontend's Reset did nothing. With GPU Frame Hand-over, the picture is handed over on the GPU after a Reset too; it stayed black with "the frontend's Vulkan device was made without VK_KHR_external_memory_fd", as the core forgot what the frontend's device had been made with.
- Output Resolution can also be 960x540 or 640x360, for slow machines: a smaller picture is cheaper to read back from the GPU and to hand over. The game still renders at its own resolution.
- GPU Frame Hand-over on Windows too. The emulator's images are handed over by NT handle, which the core duplicates from the emulator's process, where Linux uses a descriptor sent over a socket. Not yet run by anyone: it has been built, and there was no Windows machine to try it on.
- Linux on ARM (aarch64), experimental: a core for an ARM frontend. It cannot run the emulator itself, as that runs the game's x86-64 code on the CPU, so it starts the x86-64 build of the emulator as its second process through box64 and trades with it through the same shared memory. The core is a single file: it carries box64 and the x86-64 build, and writes them into the system directory, `shadPS4/x86_64/`, when they are not there from the same build. Tried on one machine (Snapdragon 7c, Adreno 618 with Turnip, RetroArch on its `gl` driver): Sonic Mania plays, fairly well but not fully smoothly, and its sound stutters a little where the emulator falls behind. box64 is run with exact CPU flags (`BOX64_DYNAREC_SAFEFLAGS=2`): with its faster default the game's music stayed silent while the sound effects played. The option System > Exact CPU Flags, on by default and only in the ARM core, turns them off for games that do not need them, which is faster; as a per-game option in RetroArch it can differ from game to game.
- Devices with little sparse address space or without sparse residency for buffers (Adreno 618 has 4 GiB and none) no longer fail at the first buffer with `ErrorOutOfDeviceMemory`: the buffer cache's arenas are sized to what the device has, and residency is asked for only where it exists. Other devices are untouched. Tried on an Adreno 618 (Turnip) with upstream's standalone emulator built from the same commit with this change, run through an x86-64 translator: the arenas came out at 64 MiB and Sonic Mania reached its title screen, where it stopped at the first buffer before. Judged from the log; the picture was not looked at, and the core itself has not run on that machine yet.
- Linux: a new core option, GPU Frame Hand-over, off by default. With it RetroArch draws the emulator's finished frames straight from the GPU, in place of each one being read back into system memory and uploaded again. It needs RetroArch's `vulkan` video driver. The emulator makes its device on the GPU RetroArch is on, as the two have to share one; where the hand-over still cannot be done the picture stays black and a message says why. On one Linux machine (Ryzen Embedded R1606G, Radeon Vega 3, Mesa RADV), on Sonic Mania's title screen, RetroArch's process went from 33 % of one CPU core at 1280x720 and 68 % at 1920x1080 to 4 % at either, the emulator's from 27 % and 42 % to 23 %, and 3840x2160 from 43 frames a second to the full 60. Played into the first level there, and through RetroArch going to a window and back to full screen. With RetroArch's `glcore` driver the option leaves the picture going through system memory, as it says. Not run on any other GPU or driver, and the choice of RetroArch's GPU not on a machine with more than one.
- The picture costs less on its way to the frontend. The emulator made a buffer for every frame it read back from the GPU and now uses them again, and the core hands RetroArch the frame from the shared memory in place of a copy of it. On one Linux machine (Ryzen Embedded R1606G, Radeon Vega 3), on Sonic Mania's title screen, the emulator's process went from 40 % of one CPU core to 27 % at 1280x720 and from 64 % to 42 % at 1920x1080, and RetroArch's from 37 % to 33 % and from 75 % to 68 %.
- Output Resolution 3840x2160 no longer ends the emulator with "Failed allocating buffer with error ErrorOutOfDeviceMemory", which came from those per-frame buffers on a machine with little video memory. Tried on the same machine: the game starts and runs there at about 43 frames a second.
- A new core option, Copy GPU Buffers, on by default: the emulator copies a game's command buffers when they are submitted. Sonic Mania stopped with "Out of order flip IRQ" on entering Mania Mode because it built its next frame over a command buffer the emulator had not drawn yet, which the core's late presentation makes a regular thing; with the emulator's own setting for this turned on in its config file the game ran on through that point on Linux, twice. The option itself is not yet run by anyone.
- The frontend is told the names of the controls: RetroArch's Controls menu showed nothing for the core's ports, and now lists the PS4 buttons and sticks of as many ports as the Controllers option says. Not yet run by anyone.
- A race in the emulator's wait for an idle GPU thread is closed: an idle signal that arrived late could release the game to submit its next frame while a command buffer was still waiting. It was meant to end Sonic Mania stopping with "Out of order flip IRQ" when Mania Mode is entered, and does not: the game still stops there with this build, on Linux. Standalone 0.19.0 does not stop there.
- Linux: a crash of the emulator is reported at once. The system wrote a core dump of the emulator's process first, which is the console's whole address space: it took over a minute, could use up the machine's memory, and until it was done the frontend showed a still picture with no message. The process no longer leaves a core dump. Tried on Linux by setting the same limit on a running core from outside, not yet with a build.
- The hidden window is no longer given an icon. Nobody sees it, and on Linux its video driver cannot take one, so every start logged an error about it. Tried on Linux.
- A game that ends itself closes the content without a crash report: its `exit()` ended the emulator's process through the assertion handler, so the frontend showed the message meant for a crash and the system wrote a crash report for a game that had quit on its own. The process now ends the way it does when content is closed, and the message about a crash is kept for a process that was really killed; a game that ends with an error status of its own is reported as that. Tried on Linux with a homebrew sample that ends itself, not yet with a game.
- The recipe for libretro's buildbot builds the Windows core too: its MSVC is too old for shadPS4, so the job cross-builds on Linux with clang-cl against the MSVC runtime and Windows SDK (`.ci/build-windows-cross.sh`). A GitHub workflow replays the job.
- Sound: a game's audio ports are paced by what the frontend takes, and about 65 ms is queued at most. They were paced by the clock, so a frontend running slightly slower than the game's sound let up to a third of a second pile up as latency, with part of it thrown away now and then. Not yet run by anyone.
- Linux: the emulator's hidden window is on SDL's offscreen video driver, and SDL is built without the X11 and Wayland backends, so the core needs no display server of its own and builds without their headers. Not yet run by anyone.

## Test build 1 - 2026-10-11

The first build of the core. Based on upstream shadPS4 3a9f572. It has been built for Windows and Linux x86_64 and not yet run on real hardware by anyone: games may not start at all.

### The core

- The emulator builds as a libretro core, `shadps4_libretro`. Loading a dumped game's `eboot.bin` starts it.
- The core does not run the emulator inside the frontend's process. It starts itself again in a second process and trades with it through shared memory: the picture and the sound come out, the pads and the core options go in, the pads' motors come back. On Windows the second process is `rundll32.exe` loading the core; on Linux it is a small launcher carried inside the core and run from memory.
- Closing content ends that process and leaves the frontend running. Another game can be loaded afterwards.
- A game that crashes, or quits on its own, does not take the frontend with it: the frontend is told to close the content, and after a crash a message says so.
- The emulator's process ends with the frontend however the frontend ends.
- Everything the emulator writes (settings, logs, saves, shader cache) goes under the frontend's system directory, in `shadPS4/`.

### Picture, sound and pads

- The picture is shown by the frontend. The renderer draws into images of its own in place of a swapchain, and each finished frame is read back from the GPU and handed over as a software frame, so it does not depend on the frontend's video driver. The emulator's own window is still created, but hidden.
- The picture is the Output Resolution exactly, and that is also the largest picture the frontend is told to expect.
- The sound is played by the frontend. Each of the game's audio ports is converted to 16-bit stereo at 48 kHz and they are mixed; every frame the frontend gets one frame's worth, with silence for what is missing.
- Up to four controllers: the Controllers option says how many of the frontend's ports are connected to the console (one by default). Buttons, both sticks, analog triggers and rumble; Select is the touchpad button. SDL's own gamepad handling is off in the core, so a pad is not read twice.

### Core options

- Twenty-five options in five categories, set on top of the emulator's own configuration when a game starts, with the standalone's defaults. System: PS4 Pro Mode, Console Language, Devkit Console Mode, Additional Memory, Confirm Button, Connected to Network, Controllers, Show Splash Screen. Video: Output Resolution, FSR Upscaling, FSR Sharpening, FSR Sharpening Strength, VBlank Frequency, GPU Readbacks, Direct Memory Access, Readback Linear Images, Shader Cache, Show FPS Counter. Audio: Volume. Trophies: Trophy Notifications, their position and duration. Logging: Logging, Separate Log Files, Log Sync.
- The option texts can be translated through libretro's Crowdin project: `intl/` scripts, the upload and sync workflows, and `libretro_core_options_intl.h` (all English until the first sync).

### Repository and builds

- The repository holds the core only: upstream's standalone entry point, packaging files, tests, documents and contributor files are removed (`.upstream-excluded`), and the README describes the core.
- CI builds the core for Linux and Windows x86_64 (`.github/workflows/libretro.yml`), in place of upstream's workflow.
- A recipe for libretro's buildbot (`.gitlab-ci.yml`), Linux x64, and a GitHub workflow that replays it (`gitlab-preflight.yml`). The core info file is in libretro's full format.

### Known limits

- x86-64 only: the emulator runs the game's code directly on the host CPU.
- The picture is copied through system memory on its way to the frontend, which costs speed at high output resolutions.
- No save states: the emulator has none.
- Core options take effect when the next game is started, not while one runs. A setting without a core option is in the emulator's own config files under `system/shadPS4/`, and a per-game setting there wins over the core option.
